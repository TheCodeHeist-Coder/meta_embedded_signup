1. What I Learned — The Core Idea

Embedded Signup is a secure OAuth flow that lets a customer connect their WhatsApp Business account to the Cloud API without ever leaving your application. Rather than redirecting to Facebook, the user authenticates inside an SDK-launched dialog and your app receives a short-lived authorization code, which the backend exchanges for a long-lived access token.

Why it matters

  • Seamless UX — no external redirects
  • Secure server-side token handling
  • Supports multiple WhatsApp accounts (multi-WABA)
  • Optional Coexistence with the WhatsApp Business App

Coexistence Mode

Lets a business run the WhatsApp Business App (manual 1:1 chats) and the Cloud API (automation) at the same time, with message & history synchronization between them. It requires a special signup configuration (see §4).

2. How the Flow Works (Architecture)

Browser User clicks “Sign up with WhatsApp” → FB SDK opens login dialog → user authorizes → receives code (30s TTL) → sent to backend
Backend Receives code → exchanges for Access Token + WABA ID → stores encrypted → starts sync (if coexistence)
Webhooks Meta pushes messages, account_update, history, etc. → process async → respond to customers

The whole exchange hinges on speed: the authorization code is valid for only 30 seconds, so the frontend must forward it and the backend must redeem it with zero delay.

4. Standard vs. Coexistence Configuration

Standard Mode

const config = {
  config_id: "YOUR_CONFIG_ID",
  response_type: "code",
  override_default_response_type: true,
  extras: { setup: {} }
};

Coexistence Mode

const config = {
  config_id: "YOUR_CONFIG_ID",
  response_type: "code",
  override_default_response_type: true,
  extras: {
    setup: {},
    featureType:
      "whatsapp_business_app_onboarding",
    sessionInfoVersion: "3"
  }
};
Key difference: Coexistence adds featureType + sessionInfoVersion: "3", unlocking simultaneous use of both apps with message syncing. It also caps sending at 20 messages/second.

5. The Critical Code — Immediate Token Exchange

⚠ 30-Second TTL. The single most important lesson: the authorization code expires in 30 seconds. No await on slow work, no user prompts, no batching — forward and exchange it immediately, or you get Error 190 “Code expired.”

Frontend — forward instantly

const fbLoginCallback = (response) => {
  if (response.authResponse) {
    const code = response.authResponse.code;
    fetch('/api/auth/exchange-code', {
      method: 'POST',
      headers: {'Content-Type':'application/json'},
      body: JSON.stringify({ code })
    }).catch(e =>
      console.error('Exchange failed:', e));
  }
};

Backend — redeem instantly

app.post('/api/auth/exchange-code',
  async (req, res) => {
  const { code } = req.body;
  const r = await axios.post(
   'https://graph.facebook.com/v25.0/oauth/access_token',
   { client_id: process.env.APP_ID,
     client_secret: process.env.APP_SECRET,
     redirect_uri: process.env.REDIRECT_URI,
     code });
  const { access_token, user_id } = r.data;
  // TODO: persist token securely
  // (DB not built yet — Day 1)
  res.json({ success: true });
});

6. Webhook Integration

Webhooks must use HTTPS, verify the X-Hub-Signature-256 signature, respond 200 immediately, then process asynchronously. The six event types I studied (full handlers are a next step):

EventPurposeHandler Action
account_updateAccount connected / disconnectedUpdate business status
messagesCustomer sends a messageSave & route message
message_statusDelivery / read updatesUpdate message status
historyChat history sync (coexistence)Store message history
smb_app_state_syncContact sync (coexistence)Sync contacts
smb_message_echoesMessages sent from the Business AppMirror to Cloud API
// Verify (GET) then handle (POST) — respond fast, process later
app.get('/webhook', (req, res) =>
  req.query['hub.verify_token'] === process.env.WEBHOOK_VERIFY_TOKEN
    ? res.send(req.query['hub.challenge']) : res.sendStatus(403));

app.post('/webhook', express.json(), (req, res) => {
  res.status(200).send('ok');                       // ACK immediately
  setImmediate(() => req.body.entry?.forEach(e =>
    e.changes?.forEach(({ field, value }) => route(field, value))));  // process async
});

8. Environment & Security

Environment Variables (used so far)

FACEBOOK_APP_ID=your_app_id
FACEBOOK_APP_SECRET=your_app_secret
FACEBOOK_CONFIG_ID=your_config_id
REDIRECT_URI=https://you.com/callback
WEBHOOK_VERIFY_TOKEN=your_token

Security Notes

  • HTTPS everywhere (front, back, webhooks)
  • Verify X-Hub-Signature-256 on webhooks
  • Secrets only in env vars, never in code
  • Rate limit: 20 msg/s (coexistence)
  • Validate all input; use CSRF protection
  • Next step: encrypt & persist access tokens once a DB is added

10. Key Takeaways

  • 30-second TTL is everything — exchange the authorization code immediately.
  • Coexistence needs special config — distinct featureType & sessionInfoVersion.
  • Webhooks must be fast — ACK 200 first, process asynchronously.
  • Security first — HTTPS everywhere and verified webhook signatures.
  • Today's milestone — working frontend signup flow + initial token-exchange backend.
